# ผลการทำงานวัน 2 — ข้อความไทย/อังกฤษ

## Logic ที่เพิ่ม

`analyzer.py` คืน signal หนึ่งครั้งต่อกลุ่ม พร้อม `id`, `weight`, `reason` แล้วรวมคะแนนไม่เกิน 100 คะแนนนี้เป็น **heuristic** ไม่ใช่เปอร์เซ็นต์ความน่าจะเป็น

| Signal | น้ำหนักเริ่มต้น | เหตุผลของการตั้งค่า |
|---|---:|---|
| `requests_secret` | 70 | การขอ OTP/รหัสผ่านมีความเสี่ยงสูงพอให้ HIGH เดี่ยว ๆ |
| `account_threat` | 25 | การอ้างปัญหาบัญชีเพียงอย่างเดียวยังไม่พอให้ HIGH |
| `link_with_account_action` | 35 | ลิงก์ร่วมกับคำชวนยืนยัน/ปลดล็อก/กรอกรหัส เพิ่มความเสี่ยง |
| `requests_transfer` | 20 | คำว่าโอนเงินพบในธุรกรรมปกติ จึงเริ่ม LOW เมื่ออยู่เดี่ยว ๆ |
| `requests_personal_data` | 35 | คำขอข้อมูลอ่อนไหวเริ่ม MEDIUM |
| `fear_or_urgency` | 15 | นับความเร่งด่วนเฉพาะเมื่อมีการอ้างปัญหาบัญชี |

เมื่อมี signal: `LOW` = 1–24, `MEDIUM` = 25–59, `HIGH` = 60–100 หากไม่พบ signal: `insufficient_evidence` กับ `risk: null`, `score: null` น้ำหนักและเกณฑ์ต้องทบทวนหลังทดสอบกับตัวอย่างใหม่

## ผลทดสอบจริง

- `python -m unittest discover -s tests -v`: ผ่าน **16 tests** รวมการตรวจตัวอย่างสังเคราะห์ใน `tests/cases.json`
- ตัวอย่างข้อความ **18 กรณี** ตรงกับผลคาดหวังที่กำหนดไว้ ตัวอย่างเหล่านี้ใช้สร้างและแก้กฎ จึง **ห้ามนำไปอ้างเป็น accuracy**
- ตัวอย่าง URL แบบส่งเดี่ยว ๆ ยังไม่รองรับ และไม่ได้รวมในการประเมินข้อความ

## Bug และการแก้

1. ข้อความเตือน “อย่ากดลิงก์” ถูกจัด HIGH เพราะกฎจับคำว่า “กดลิงก์” โดยไม่ดูคำห้าม → เพิ่มการตรวจคำห้ามก่อนคำชวนทำรายการ
2. ข่าวอบรมธนาคารที่มี URL ถูกนับเป็นลิงก์เพื่อทำรายการการเงิน → ให้กฎลิงก์ต้องพบการกระทำอ่อนไหว เช่น ยืนยันข้อมูล ปลดล็อก หรือกรอกรหัส

## สิ่งที่เจ้าของโปรเจกต์ควรอธิบายได้

- **ส่วนนี้ทำอะไร:** แปลงข้อความเป็นกลุ่มสัญญาณ แล้วรวมคะแนนและเลือกคำแนะนำจากสัญญาณที่พบ
- **ทำไมใช้วิธีนี้:** กฎสั้นและตรวจสอบเหตุผลได้ เหมาะกับ MVP ที่ต้องอธิบาย source code ได้
- **Input/output:** รับข้อความหนึ่งรายการ คืนสถานะ risk/score หรือ null, signals และ actions; ไม่เก็บ input
- **ข้อจำกัด:** คำสะกดเลี่ยงและข้อความที่ใช้บริบทซับซ้อนอาจหลุด; คำห้ามตรวจแบบใกล้คำกริยาเท่านั้น; การมีลิงก์ไม่ได้ยืนยันว่าโดเมนอันตราย; น้ำหนักยังไม่ได้ calibrate
- **ประเด็นสำหรับการนำเสนอ:** `insufficient_evidence` ไม่ใช่ LOW, และผลที่ตรงกับชุดตัวอย่างที่ใช้สร้างกฎไม่ได้พิสูจน์ความแม่นยำกับข้อความใหม่
