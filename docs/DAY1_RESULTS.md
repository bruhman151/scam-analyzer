# ผลการทำงานวัน 1 — 5 ตุลาคม 2026

## สิ่งที่ตรวจและทำได้จริง

- เครื่องพัฒนามี Python 3.14.3 และ Flask 3.1.3 ใช้งานได้ แต่คำสั่ง `python` แบบสั้นชี้ไปที่ Windows App alias ที่เปิดไม่ได้ จึงทดสอบด้วย Python executable ที่ติดตั้งจริง
- ยังไม่พบ `tesseract.exe` ใน PATH หรือสองตำแหน่งติดตั้งมาตรฐานบน Windows **ยังไม่ได้ทดสอบ OCR ไทย/อังกฤษ**
- `python -m unittest discover -s tests -v`: ผ่าน **7 จาก 7 tests** ที่เขียนสำหรับส่วนวัน 1
- เปิด Flask service ในเครื่อง แล้วส่ง HTTP `POST /analyze` จริง ได้สถานะ 200 พร้อม `risk: HIGH`, `score: 70`, `requests_secret` สำหรับข้อความสังเคราะห์ที่ขอ OTP
- ตรวจไฟล์ `tests/cases.json` ว่าเป็น JSON ที่อ่านได้

## ผลเทียบกับตัวอย่างที่วางแผนไว้

ทดสอบข้อความ **15 ตัวอย่าง** ใน `tests/cases.json` กับกฎที่มีอยู่วันนี้ ผลตรงกับที่คาดไว้ **9 ตัวอย่าง** อีก **6 ตัวอย่าง** ยังไม่พบสัญญาณ เพราะหมวดบัญชีถูกอายัด, URL phishing, โอนเงิน, ขอข้อมูลส่วนตัว และข้อความหลอกที่เขียนเนียนยังไม่ได้ implement ตัวเลขนี้เป็นความคืบหน้าของชุดตัวอย่างเล็ก ๆ **ไม่ใช่ accuracy ของระบบ** ตัวอย่าง URL แบบแยกเดี่ยวยังไม่ได้รัน เพราะ API รองรับเฉพาะข้อความ

## Bug ที่พบจากการพยายามทำให้ระบบพลาด

1. ก่อนแก้: “ห้ามส่งรหัส OTP ให้ใครเด็ดขาด” และ “Do not share your verification code” ถูกจัด HIGH เพราะกฎไม่ดูคำห้าม หลังแก้: ทั้งสองเป็น LOW และเพิ่ม regression tests
2. ระหว่างแก้: ข้อความ “ห้ามบอกรหัส OTP ให้คนอื่น แต่ส่งรหัส OTP ให้เจ้าหน้าที่” กลับถูกจัด LOW เพราะ regex จับช่วงยาวผ่านคำขอครั้งที่สอง หลังแก้ให้จับช่วงสั้นที่สุด: จัด HIGH และเพิ่ม regression test

การดูคำห้ามยังเป็น heuristic ใกล้คำกริยา ไม่เข้าใจประโยคทุกแบบ ต้องทดสอบต่อเมื่อขยายกฎ

## รายการให้เจ้าของโปรเจกต์ review ก่อนวัน 2

1. ชื่อสัญญาณ `requests_secret` และคำอธิบายไทยตรงกับความหมายที่ต้องการหรือไม่
2. น้ำหนัก OTP request = 70 และเกณฑ์ HIGH ตั้งแต่ 60 เป็นเพียงค่าเริ่มต้น จะปรับเมื่อมีกฎหลายตัวและผลทดสอบ

## การตัดสินใจหลัง review

เจ้าของโปรเจกต์เลือกให้กรณีไม่มีสัญญาณเป็น **“หลักฐานไม่พอ”** แทน LOW จึงปรับ API ให้คืน `insufficient_evidence` กับ `risk: null` และ `score: null` ผลทดสอบส่วนก่อนหน้านี้ยังคงบันทึกตามเวลาที่รันจริง
